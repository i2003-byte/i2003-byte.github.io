📘 Learn the science

💡 The big idea

Searching means finding one item in a list. A computer can only look at one item at a time, so we measure a search by the number of checks (comparisons) it makes.

  • Linear search starts at the first student and checks each one in turn until it finds the roll number or reaches the end. It works on any list, sorted or not.
  • Binary search uses the fact that the register is sorted. It checks the student in the middle. If that roll number is too small, the one we want must be in the second half, so the whole first half is thrown away in one go; if it is too big, the second half goes. Each check halves the part that is still possible.

That is why you open a dictionary near the middle instead of reading it from page 1: halving finds a word among lakhs in a few steps.

🧮 Key formulas & rules

Linear search: worst case n checks, on average about (n + 1) ÷ 2 if the item is there Binary search: worst case ⌊log₂ n⌋ + 1 checks n = 40 → 6 checks · n = 100 → 7 · n = 500 → 9 · n = 10 lakh → 20 middle = ⌊(low + high) ÷ 2⌋
  • log₂ n is how many times n can be halved before 1 is left. Doubling the list adds only one check to binary search, but doubles the work of linear search.
  • Binary search needs a sorted list. Sorting first costs time (see the Sorting Race), so it pays off when you search the same list many times.

Simplification: one check takes the same time in both searches. Roll numbers here are made up and increase by 1 to 3 from student to student, so you cannot simply jump straight to the right place.

🌍 In real life

  • Finding your name in a printed exam result list sorted by roll number: you flip to about the right page, then halve again and again.
  • Railway reservation and bank systems keep records sorted (or in trees built on the same idea) so one record out of crores is found in a few dozen steps.
  • Git's bisect command finds which change broke a program by binary search through its history.
  • A shuffled pile of answer sheets has to be searched one by one: linear search is the only choice.

🎯 Try this

  1. With 40 students, press Start searching. How many checks does each search need to find the roll number?
    Show answerLinear search needs 25 checks (it is the 25th student). Binary search needs only 3: the middle (too small), the middle of the second half (too big), then the middle of what is left (found).
  2. Choose 100 students and press "Find one that is not there". How many checks does each search need before it can say "not found"?
    Show answerLinear search must check all 100. Binary search gives up after at most 7, when nothing is left between low and high.
  3. Tap the very first student in the register to search for them. Which search wins now?
    Show answerLinear search: it finds the first student in 1 check, while binary search starts in the middle and needs 5 or 6 checks. Binary search is better on average and in the worst case, not every single time.
  4. Choose 500 students and try several roll numbers. Does binary search ever need more than 9 checks?
    Show answerNo. 2⁹ = 512 ≥ 500, so after at most 9 halvings only one student is left. Linear search often needs hundreds.
  5. Switch the register to "Shuffled" and search a few times. What goes wrong with binary search?
    Show answerIt often says "not found" even though the student is there. Throwing away half the list is only safe when the list is sorted; in a shuffled list the number may be hiding in the half it threw away.

📖 Key terms

  • Linear (sequential) search: checking items one after another from the start.
  • Binary search: repeatedly checking the middle of a sorted list and discarding half.
  • Best, average and worst case: the fewest, typical and most steps an algorithm can need.
  • O(n) and O(log n): short ways of saying the steps grow like n or like log n.
