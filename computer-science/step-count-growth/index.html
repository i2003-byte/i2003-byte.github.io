📘 Learn the science

💡 The big idea

For a small list, every algorithm is fast. What matters is how the number of steps grows as the list gets bigger. This is called the algorithm's time complexity. Four common patterns:

  • log n (binary search): doubling the list adds just one step.
  • n (linear search): doubling the list doubles the steps.
  • n log n (merge sort): a little more than doubles.
  • n² (bubble and selection sort): doubling the list makes four times the work; ten times the list makes a hundred times the work.

For 10 items the difference hardly matters. For 10 lakh items it is the difference between a blink and an hour, and for 100 crore items between seconds and centuries.

🧮 Key formulas & rules

time = number of steps ÷ steps per second n = 10 lakh at 10⁸ steps/s: log₂ n ≈ 20 steps → 0.2 µs · n → 10 ms · n log₂ n ≈ 2 crore → 0.2 s · n² ÷ 2 = 5 × 10¹¹ → about 1.4 hours n = 100 crore (10⁹): n² ÷ 2 = 5 × 10¹⁷ steps → about 160 years on a laptop
  • On log axes every grid line is 1,000 times the one before, so huge and tiny numbers fit on one chart and n, n², log n become straight-ish lines with different slopes. On ordinary axes n² shoots off the top almost at once.
  • A faster computer divides every time by the same number; a better algorithm changes how the time grows. For big n, a better algorithm beats a faster computer.

Simplification: these are worst-case step counts (merge sort and binary search rounded to n log₂ n and log₂ n), and every step takes the same time. Real programs also spend time reading memory and their speed varies.

🌍 In real life

  • Aadhaar has more than 100 crore records. Finding one by linear search would take seconds per lookup; with sorted indexes (the log n idea) it takes microseconds, so crores of checks a day are possible.
  • Board exam results for about 10 lakh students must be sorted by marks. An n log n sort finishes in under a second; an n² sort would take over an hour on the same computer.
  • Programmers check the complexity of their code before running it on big data: an n² step hidden in a loop is a common reason apps slow down as they grow.

📖 Key terms

  • Time complexity: how the number of steps grows with the input size n.
  • Big O: a short way to write it, e.g. O(log n), O(n), O(n log n), O(n²).
  • Log scale: an axis where equal distances mean equal multiplication (×10 or ×1000), not equal addition.
