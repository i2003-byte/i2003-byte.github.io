💡 The big idea

An algorithm is a precise list of steps that solves a problem. Sorting (putting things in order) can be done by many different algorithms, and some need far more work than others. A computer sorts by comparing two items and moving them, so we measure an algorithm by counting those steps. Here the same shuffled bars are given to three algorithms, and each gets one step per tick:

  • Bubble sort walks along the row comparing neighbours and swaps any pair that is the wrong way round. After each pass the largest remaining bar has "bubbled" to the end. If a pass makes no swap, the row is sorted and it stops early.
  • Selection sort scans the unsorted part to find the smallest bar and swaps it to the front. It always scans everything, even if the row was already in order.
  • Merge sort splits the row into halves, sorts each half the same way, then merges the two sorted halves by repeatedly taking the smaller of the two front bars. The shaded band shows the part being merged.

🧮 Key formulas & rules

Selection sort comparisons = (n − 1) + (n − 2) + … + 1 = n(n − 1) ÷ 2 Bubble sort comparisons ≤ n(n − 1) ÷ 2 (only n − 1 if already sorted) Merge sort comparisons ≤ about n × log₂ n n = 64: n(n − 1) ÷ 2 = 2016 but n × log₂ n = 384
  • Work that grows like n² becomes 4 times bigger when n doubles. Work that grows like n log n only becomes a little more than 2 times bigger.
  • log₂ n is how many times you can halve n before reaching 1: log₂ 64 = 6, because 64 → 32 → 16 → 8 → 4 → 2 → 1.

Simplification: every comparison, swap or write counts as one step of equal time. Real computers take different times for these, and merge sort also needs extra memory for its copy of each half.

🌍 In real life

  • A teacher arranging 40 answer sheets by roll number: picking out the lowest each time is selection sort; splitting the pile between two helpers and merging their sorted piles is merge sort.
  • Online shops sort lakhs of products by price in a fraction of a second, using n log n algorithms such as merge sort or quicksort. An n² algorithm would take hours.
  • Python's built-in sorted() uses Timsort, a mix of merge sort and insertion sort that is extra fast on nearly sorted data.

🎯 Try this

  1. Race 16 shuffled bars a few times with "New shuffled array". Does selection sort's comparison count ever change?
    Show answerNo. It is always 15 + 14 + … + 1 = 120, because selection sort scans the whole unsorted part every time, whatever the order. Bubble and merge sort counts change with the order.
  2. Choose "Nearly sorted". Which algorithm wins now, and why?
    Show answerBubble sort. One pass fixes the few swapped neighbours, and the next pass makes no swap, so it stops after about 2n comparisons. Selection sort still does all 120, and merge sort still writes every bar about log₂ n times.
  3. Choose "Reversed". How many swaps does bubble sort make with 16 bars?
    Show answer120: every pair of bars is in the wrong order, so every comparison leads to a swap. This is the worst case for bubble sort. Selection sort needs only 8 swaps here.
  4. Race only 8 bars several times. Does merge sort still win?
    Show answerUsually not. With so few bars, n(n − 1) ÷ 2 and n log₂ n are close (28 and 24), and merge sort also writes every bar once per level (24 writes), so selection sort often finishes first. Merge sort's advantage shows for large n.
  5. Compare the selection sort comparisons for 32 and 64 bars. Then do the same for merge sort.
    Show answerSelection sort: 496 → 2016, about 4 times. Merge sort: at most 129 → 321 (always below n log₂ n = 160 → 384), about 2.5 times. Doubling n quadruples n² work but only a little more than doubles n log n work.

📖 Key terms

  • Comparison: checking which of two items is bigger. Swap: exchanging two items.
  • Pass: one full walk along the unsorted part of the list.
  • Divide and conquer: solving a problem by splitting it into smaller copies of itself, as merge sort does.
  • Time complexity: how the number of steps grows with n, written O(n²) or O(n log n).
